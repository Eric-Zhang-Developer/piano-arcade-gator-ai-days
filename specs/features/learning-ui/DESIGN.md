# Learning room

Mode: Operate. Desktop/laptop only. The accepted learning mockup supplies question/workspace adjacency; the published `piano-learning` plan on `seeko/work` supplies the four activity distinction and evidence boundaries. This slice is a frontend starting point, not the learner engine.

The actual mlhacky.com app was inspected by the reference scout, then compared with the first working Next baseline. Its quiet chrome, readable type, dominant workspace and progressive disclosure are observations, not a published author manifesto. Apply those qualities without copying its branding or chat history.

A quiet piano studio: ink/slate frame, warm ivory score, dark notation and one brass action accent. Hanken Grotesk supports controls and questions; Newsreader gives musical titles an editorial voice. Fonts are self-hosted through Next. Shared `--learn-*` variables live in `learning.module.css` and style procedural components too.

Four direct navigation entries replace nested mode selectors. The current task sits on the left; music/reference occupies the larger right pane. One primary action remains in each state. Remove repeated mode headings, navigation descriptions, global status strips and speculative progress. Source details and preview limitations are disclosures. Retain question context, real feedback, accessible labels, score provenance and visible demo boundaries.

Notation and audio use the existing cited Twinkle chart. Melodic closure is distinct from harmonic cadence evidence. Closed responses are actually checked; explanations compare with original reference copy. Procedural takes are explicitly scripted and do not record or grade a piano performance.
