# Learning room

Read the frozen [Product philosophy](../../../PRODUCT_PHILOSOPHY.md) before
product, UI or code decisions. This surface must carry its promise of a
reassuring personal tutor, useful challenge and growing independence; the
implementation choices below serve that promise.

Mode: Operate. Desktop/laptop only. The accepted Spark question/workspace arrangement remains the session layout. The current increment makes the graph home gator-guided: one prepared next activity, a short reason, and one primary Start/Resume action. It enters the matching activity directly with the skill and musical example already selected. The learner need not choose Learn/Review, Theory/Procedure or a graph node first. The prepared skill chooses the graph domain; datasets remain separate and the map is read-only. Existing Learn/Review hub URLs redirect to the map. The brand returns to the agent/map home. No dashboard metrics, invented mastery or automatic session entry.

Visual authority is Eric-authored main `5c1bb0e641a3a40cd1968a70ba05c488d597fbcb`: `specs/context/visual-direction.md`, root `globals.css`/`layout.tsx`, and select-layout, song-card, options-panel and pause-skin CSS. Saira is loaded once by the existing root Next font. The wordmark and activity headings use italic 900; song titles, menu/navigation and main actions use italic 800; questions, labels and reading use system-ui. In particular, procedural action styles outrank the shell's generic button font reset. Fonts were checked against the rendered shared select on this branch, whose font declarations match current main, and document.fonts/width metrics verify the actual loaded faces rather than a similarly named fallback. The newest open [pause integration](https://github.com/Eric-Zhang-Developer/piano-arcade-gator-ai-days/pull/404), head `ed58c9a909bb40dfe725e7872514cba4eb2191d6`, changes only the play route and introduces no replacement font system.

Existing `--pa-*` tokens supply black/violet surfaces, white ink, cyan selected controls/actions and magenta keyboard focus. Local `--learn-*` aliases style both theory and procedural sessions. Mint/azure remain hand colors and gold remains a real gameplay rank/record color. Learning imports no gameplay state or scenery. The dark score surface uses the shared panel RGB with off-white notation and subdued staff lines. SVGs explicitly inherit foreground fill so clefs, time signatures, note labels and bar numbers remain visible. Hollow noteheads retain the score background. Treble glyphs retain their serif/music fallback and all note geometry is unchanged. Existing audio state can emphasize the playing theory phrase; the existing procedural playhead uses cyan. No invented playback state is shown.

`LearningSessions.tsx` owns actual in-memory state in the persistent learning layout: separate Learn/Review answers, history and selected material; practice settings/repetitions/results; Review practice result. Start is shown before entry; Resume is offered only for an actual unfinished local session and restores its real stopped state. Completion shows its result with a primary return to the agent/map home; explicit secondary repeat actions may reset completed sessions. The prepared fixture supplies the domain and target independently of actual started-session state. The module-level prepared fixture stays unchanged across graph navigation; the provider supplies session continuity, not a connected agent or scheduler. Activity cleanup cancels audio and returns active takes/count-ins to safe stopped state. See [Learning preview](../../../README.md#learning-preview) for navigation continuity and reset boundaries; the proposed route has its own isolated provider. No account, persistence service, AI grading or piano capture is connected. Procedural workspaces retain visible demo labels.

Theory follows Spark encoding workspace source `c8e36dc`: `src/App.tsx`, `src/styles.css` and `src/components/LearningFocus.tsx`. Below the top bar, it is a flat full-height 40/60 split with 330px question and 430px material minima, a persistent musical task, independently scrolling questions/history and materials, a pinned response/action region, and a keyboard/pointer divider. Learn keeps the selected material while questions advance. Review resets to Music and re-locks Reference on each question. No Spark chat/backend is imported.

Notation and audio use the repository's cited Twinkle chart. Melodic closure is distinct from harmonic cadence evidence. Closed answers are computed; explanations compare with original reference copy. Practice takes are scripted, with feedback after the attempt and self-reported repetitions. Unknown progress stays unknown.

Eric's committed visual evidence was inspected in visible background Chrome: main `c035a4fcab7d8749f73dabdaf10b73378fc8f164` select capture and [Options drawer](https://github.com/Eric-Zhang-Developer/piano-arcade-gator-ai-days/pull/345) captures at `4730a18ddb979f5f198e8942036418f27c4ff173`. A background viewport screenshot omission of rail glyphs was distinguished from actual rendering by a rail-only capture showing every item. The rail has since been superseded by the requested top navigation.

The overall home is a read-only guided map in `graph/MasteryGraphHome.tsx`. The prepared skill selects its Theory or Procedure dataset; students do not switch domains, inspect nodes, pan, zoom, hide the guide or choose a learning mode. Legacy category hubs redirect to `/learn`. The prepared activity, actual session Resume and essential map return remain. This explicitly replaces the prior optional-exploration increment.

Composition authority remains the supplied Spark screenshot and actual Spark `c8e36dc` `course-graph.ts`/`CourseOverview.tsx`. Six uneven broad roots, outward leaf-weighted fans, deeper previews and curved authored relationships retain their deterministic world geometry. `layout.ts` returns x/y/z with z=0; projection/caption placement stay separate. All 134 nodes retain normalized fictional/prior mastery distributions, including 12 independently authored broad parents. Three display buckets and accessible Secure/Partial/Low plus source names are shared by parents/leaves. Raw distributions, eligibility and scheduling remain separate; no student color key or due marker is shown. No connected posterior inference, new scheduler or backend is implied.

Screen-space labels preserve the accepted 18px/600 and 14px/500 system-ui roles, .01em tracking, normal kerning and clean paint over clearance rectangles. Saira continues to supply Eric's display/action identity. During travel, captured node-relative caption anchors follow the same camera without discrete candidate reselection; unrelated captions fade. Text is never a scaled screenshot. Static collision placement and world geometry remain unchanged.

`guided-motion.ts` supplies a single spatial clock: 100ms anticipation, 1000ms cubic glide and 100ms observable arrival. The route handoff and lesson reveal follow separately, as described below. Character and slightly lagging camera share the world path; projection, modest tilt/bob and scale give 2.5D presence without a new rendering engine. The character launches from the measured 112px top-left perch. The camera ends at the actual skill at 3.2x; the pet settles 100px above its center so both node and caption remain clear.

`GuidedEntry.tsx` lives in the persistent learning layout, outside route children and offline Activity effects. One overlay image survives the route until the ready activity materializes. The original perched copy is hidden at launch. The prepared theory route now reserves a 112px slot for the same incumbent guide. Teaching material remains hidden during a roughly 550ms settle, then fades in over 200ms; the overlay is replaced in place by the resident guide, without covering score/heading content. There is no empty handoff or generated-video navigation. A run token locks double entry and cancels stale RAF/timers; offline or explicit navigation cancels the journey and restores the prepared home. After reveal, semantic focus moves to the new activity heading without an editable-looking outline; interactive keyboard focus rings remain. Reduced motion enters directly and skips travel/clip animation. No audio or take starts automatically.

The director accepts the actual contextual href/target for every supported learning/retrieval activity. The current prepared fixture remains Hearing a phrase come home, with the same real layout-owned session state and explicit completed repeat. The guide is an authored frontend demonstration, not a live agent/model decision. No free map exploration, extra mode choice, full 3D engine or speculative integration is added.
